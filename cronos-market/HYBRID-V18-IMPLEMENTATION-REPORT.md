# RIFT v18 — online startup, explicit connection lifecycle, experimental native wallet vault

**Debug engineering preview — NOT a production wallet. Do not fund generated addresses or import recovery phrases controlling real assets.** This increment does not certify perfect behavior, a two-hour elapsed session, full wallet functionality or mainnet readiness.

## Approved direction and actual scope

The user chose a built-in self-custody wallet and auto-connect on launch with explicit disconnect controls. v18 implements online-default connection behavior and a native generation/recovery/backup foundation. **Embedded transaction signing, sends, minting, listings and purchases are not implemented for the vault.** Existing external-wallet web trading is separate and still requires a compatible deployed shared API. RPC access alone cannot provide that backend, global rankings or complete NFT discovery.

## Online startup and connection controls

- New installations use Direct-read with public Cronos RPC, not implicit Offline mode, and open the bundled interface automatically. A bounded RPC chain/head check runs on launch/foreground return with visible connecting/success/failure status. Failure is not replaced by fake balances or an offline-success claim. Android cannot guarantee continuous connectivity/background execution; no perpetual foreground networking service was added.
- One-time migration changes legacy implicit offline settings with no `connectionChoice` marker to Direct-read. Previous releases did not distinguish the old default from explicit offline choices; that old intent cannot be reconstructed. New explicit disconnects persist as paused across restarts and are not automatically re-enabled.
- **Save edited settings & disconnect until validated** stores edited endpoints/keys/gateway and pauses networking. **Connect saved services** verifies the saved primary RPC reports Cronos chain 25 and a block; if a shared origin exists, its credential-free `/healthz` must report status `ok`, chain 25. Only then is Direct-read/Hybrid enabled. Typed edits must be Saved first. Gateway content checks remain separate per-fetch consent, not implicit health certification.
- **Disconnect all network services** preserves endpoints/credentials but pauses connection mode and receipt work. **Remove shared API origin & disconnect** removes that origin only. **Reset connections to public Cronos defaults** removes old provider credentials/shared origin, enables public direct reads, and leaves wallets/drafts alone. Existing explicit backup testing/swapping/removal and key deletion remain.
- Opening settings destroys the existing WebView/channels and cancels the startup probe; closing settings recreates the app using saved state. Already transmitted requests cannot be unsent. Disconnect is not remote token revocation, server logout, cookie deletion or browser-draft migration. Origin changes still require separate draft export precautions.
- Connection settings, wallet deletion and personal-workspace deletion are deliberately separate operations. No connection reset erases a recovery phrase vault or moves on-chain assets.

## Native wallet foundation

Open **My Cronos wallet · native vault** in the native app bar.

- Generate a fresh 256-bit entropy / 24-word English BIP39 wallet locally using SecureRandom; recover a TEST 12/24-word English BIP39 wallet; derive the first EVM account at `m/44'/60'/0'/0/0`. No additional BIP39 passphrase is supported; passphrase-protected wallets are NOT recovered by entering only their words. This EVM address format is not inherently Cronos-exclusive; network tools remain chain 25 only.
- One wallet/account at a time. Existing wallets cannot be silently overwritten. The UI displays/copies the public receiving address, supports a separately authenticated recovery-phrase reveal and a local backup-word challenge, checks the address's CRO balance against saved RPC, and opens native NFT tools prefilled with the public address/profile.
- Entropy is AES-GCM encrypted with an Android Keystore key requiring device authentication. Address and derivation path are authenticated associated data. Each sensitive UI action requests device credential confirmation; the underlying key allows a five-minute authentication window so phrase entry has time to complete. Device-specific hardware backing is NOT attested or promised. No app password/reset service was invented.
- A device PIN/password is required. Phrase views/inputs are native, not WebView; screen capture is blocked where supported, phrase selection/clipboard/file export are not offered, autofill/saved view state are disabled, input personalization is discouraged, overlay windows are hidden on supported Android versions and obscured Activity touches are refused, and phrase views/inputs are cleared when hidden/backgrounded. Imported text is visible to the user's keyboard: use a trusted offline keyboard. Accessibility services, physical cameras, root, debugging and a compromised OS remain threats. Java/library immutable Strings/BigIntegers cannot be reliably zeroized; byte arrays are wiped best-effort.
- Secrets are not sent to RPC, web pages, assistant, server, personal backups or file-export channels. Only the public address is passed to native NFT tools. Backup challenge completion is a user confirmation, not proof that a backup is safe.
- Authenticated local deletion requires typed confirmation and deletes the vault/key, not funds on-chain. This is not guaranteed forensic secure erase. Missing/invalidated Keystore keys fail closed with no silent reset; recovery requires the offline phrase. Clearing app data/uninstall/device security changes can lose local access. Mutations already begun may finish after navigation; reload status before retrying.
- This is a debug build with no independently reviewed custody flow. **Never import a funded wallet or use real assets. There is no embedded signer/provider bridge, send UI, transaction simulation, nonce/fee management or production account/recovery lifecycle.** Generation alone does not make the app a full wallet.

## Dependencies and executed verification

Pinned native crypto dependencies use Web3j crypto/utils 4.12.3, Bouncy Castle via utils, and SLF4J 2.0.13. Only the mnemonic/derivation/address primitives are used; crypto transitive transaction/native-KZG modules were not enabled. Exact resolved JAR hashes are recorded separately. This is not dependency/security certification; third-party rights and vulnerability review remain required, and the project still has no chosen LICENSE.

- **178 engineering tests passed**, including three new source-boundary/online-lifecycle tests. Source checks are not Android runtime execution.
- **38 native JVM tests passed**, including five wallet crypto tests. Public 12/24-word deterministic vectors matched independent ethers derivations; invalid checksum/input/entropy bounds and random entropy roundtrip were tested. Test-vector addresses must never be funded. No user recovery phrase was created or retained by the assistant.
- **6 implementation, 7 real-local-Redis security and 40 local contract tests passed.** Full implementation browsers, Worker/D1 browser and offline-fallback browser checks passed. Native transports and mobile-wallet lifecycles are mocked where stated.
- Android app/test APK build and lint passed. Final Android build rerun after strengthening test-only import warnings and overlay protections. Lint has no errors; warnings are recorded in build XML (localization/JavaScript-enabled notices), not represented as zero warnings.
- Fifteen existing instrumentation tests compiled, **none executed**. No wallet Keystore/device-auth/seed-view/recovery/deletion or online reconnect acceptance was executed on Android. That absence is a critical wallet release gate, not a minor setup step.
- Fresh final extracted source: actual npm ci, 178 engineering tests, frontend build and 38 native JVM tests passed with JDK17. An earlier extracted-source attempt was interrupted during competing Android builds; its logs are labelled interrupted, and the serial final rerun passed.
- Evidence: `checks/v18-verification.json`, `checks/v18-final-android.log`, versioned JUnit XML, `checks/v18-online-initial.log`/targeted logs. Fresh-source and package verification are recorded separately as generated.
